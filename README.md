# METHAFLOW — คู่มือส่งมอบงาน (เว็บไซต์ + Payroll Engine)

เอกสารนี้เขียนให้คนที่มารับช่วงต่อ อ่านจบแล้วทำงานต่อได้ทันทีโดยไม่ต้องถามใคร

---

## 1. โครงสร้างไฟล์ในชุดนี้

```
├── index.html              หน้าแรก
├── payroll-tools.html      หน้าเครื่องมือคำนวณฟรี
├── ewf-checker.html        หน้าตรวจเกณฑ์กองทุนสงเคราะห์ลูกจ้าง
├── ewf-guide.html          คู่มือ EWF สำหรับนายจ้าง/HR
├── doc-pricing.html        เอกสารราคาและแพ็กเกจ
├── doc-pdpa-consent.html   หนังสือให้ความยินยอม PDPA
├── privacy.html            นโยบายความเป็นส่วนตัว
├── js/
│   ├── payroll-engine.js   ★ สมองคำนวณทั้งหมด — pure functions ไม่มี DOM/network/storage
```

### ⚠ ไฟล์ที่ยังไม่อยู่ในชุดนี้ — ต้องรวมจากโปรเจกต์หลักก่อน deploy

| ไฟล์ | ใช้โดย | ถ้าขาดจะเกิดอะไร |
|---|---|---|
| `css/style.css` | ทุกหน้า | ทุกหน้าไม่มีดีไซน์เลย |
| `js/main.js` | ทุกหน้า (ยกเว้น ewf-checker/ewf-guide) | เมนู/ส่วนประกอบร่วมไม่ทำงาน |

| `js/ewf-checker.js` | ewf-checker.html | **ฟอร์มตรวจเกณฑ์กดแล้วไม่คำนวณ — หน้าใช้งานไม่ได้** |

## 2. ผลตรวจลิงก์และความสะอาดของโค้ด (ตรวจล่าสุด ส.ค. 2569)

- ลิงก์ระหว่างหน้า (`href`) ทั้ง 7 หน้า ชี้ถึงไฟล์ที่มีอยู่จริงครบทุกลิงก์ ✓ ไม่มี 404 ภายใน
- ไม่มี inline `<script>` และไม่มี event handler ใน HTML (`onclick=` ฯลฯ) แม้แต่จุดเดียว ✓
  — ผ่าน CSP `script-src 'self'` ได้ทั้งเว็บ
- มี inline `style="..."` attribute อยู่ 7 จุด (index 1 · ewf-checker 4 · ewf-guide 2)
  — เป็นเหตุผลเดียวที่ `style-src` ยังต้องมี `'unsafe-inline'` ถ้าย้ายเป็น class ใน CSS
  ครบเมื่อไร ตัด `'unsafe-inline'` ออกจาก vercel.json ได้เลย
- ลิงก์ออกนอกมีแห่งเดียว: `https://ewf.labour.go.th/` (เว็บกรมสวัสดิการฯ — เป็นลิงก์ `href`
  ธรรมดา ไม่ใช่การโหลดสคริปต์ จึงไม่กระทบ CSP)

## 3. รันเทสยังไง

```bash
node tests/run-tests.js
```

- ไม่ต้องติดตั้งอะไรเลย ใช้ Node.js เปล่า ๆ
- ตัวรันอ่านไฟล์ `.json` ทุกไฟล์ใน `tests/` อัตโนมัติ — เพิ่มไฟล์เทสใหม่แล้วรันได้ทันที
- exit code = 1 เมื่อมีเคสไม่ผ่าน (ใช้ต่อกับ CI ได้)
- **กติกาเหล็ก: เลขผิดแม้สตางค์เดียว = ไม่ปล่อยขึ้น production**

## 4. สถาปัตยกรรม engine (js/payroll-engine.js)

หลักการที่ใช้ทั้งไฟล์ — ถ้าแก้อะไรให้รักษาหลักนี้ไว้:

1. **Pure functions** — ทุกฟังก์ชันรับ input object คืน output object ไม่แตะ DOM,
   ไม่ยิง network, ไม่เก็บ state ทำให้เทสได้ 100% และใช้ซ้ำได้ทั้งบนเว็บและ backend
2. **Rule tables + `effectiveDate`** — อัตราตามกฎหมาย (เพดาน สปส., อัตรา EWF, ขั้นภาษี)
   ไม่ hardcode ในสูตร แต่เก็บเป็นตารางกฎที่มีวันบังคับใช้ เวลากฎหมายเปลี่ยน
   ให้ **เพิ่มแถวใหม่** ไม่แก้แถวเดิม เพื่อให้งวดย้อนหลังคำนวณได้ถูกต้องเสมอ
   - `pickRule` เลือกกฎล่าสุดที่มีผล ณ วันคำนวณ (มี fallback)
   - `pickRuleStrict` เหมือนกันแต่คืน `null` ถ้าไม่มีกฎ — ใช้กับกองทุนที่ยังไม่เริ่มบังคับ
3. **โมดูลหลัก vs wrapper** — โมดูลหลัก (เช่น `socialSecurity`, `ewfContribution`,
   `withholdingTax`) รับ rule table เต็มรูปแบบและเป็น "แหล่งความจริงเดียว"
   ส่วน wrapper สั้น ๆ (`sso`, `ewf`, `monthlyWht`) มีไว้ให้หน้าเครื่องมือเรียกง่าย ๆ
   และ **ส่งต่อเข้าโมดูลหลักเสมอ** — ห้ามมีสูตรซ้ำสองที่
4. **การปัดเศษ** — เงินทั่วไปปัด 2 ตำแหน่ง (`r2`) ยกเว้นเงินสมทบ สปส.
   ปัดเป็นจำนวนเต็มบาทตามแนวปฏิบัติของ สปส.

### เพิ่มโมดูลใหม่ (4 ขั้น)

1. เขียนไฟล์เทส `tests/NN-ชื่อโมดูล.json` ก่อน — กำหนด input/expected จากข้อกฎหมาย
2. เขียนฟังก์ชัน pure function ใน engine ตามลำดับเลขโมดูล พร้อมคอมเมนต์อ้างมาตรากฎหมาย
3. เพิ่มชื่อฟังก์ชันในบล็อก `return {...}` ท้ายไฟล์ และ map ชื่อโมดูลใน `tests/run-tests.js`
4. รัน `node tests/run-tests.js` ให้ผ่านครบทุกเคส (ของเดิมต้องไม่พัง) แล้วค่อย commit

## 5. การ deploy และความปลอดภัย (vercel.json)

ใช้ vercel.json ของโปรเจกต์ (ฉบับที่ทีมตั้งไว้) — ตรวจแล้วครบตามมาตรฐาน:

| ส่วน | ทำอะไร |
|---|---|
| `Content-Security-Policy` | สคริปต์รันได้จากโดเมนตัวเองเท่านั้น (`script-src 'self'`) กัน XSS · อนุญาต Google Fonts เฉพาะ CSS/font · `frame-ancestors 'none'` กัน clickjacking · `object-src 'none'` `base-uri 'self'` |
| `Strict-Transport-Security` | บังคับ HTTPS 2 ปี + `preload` |
| `X-Content-Type-Options` / `X-Frame-Options` / `Referrer-Policy` / `Permissions-Policy` | nosniff · กัน iframe · ไม่รั่ว URL · ปิดกล้อง/ไมค์/ตำแหน่ง/การจ่ายเงิน |
| `cleanUrls: true` | Vercel เสิร์ฟ URL แบบไม่มี `.html` (`/ewf-checker`) — ลิงก์ `.html` ในหน้าเว็บยังใช้ได้ (redirect อัตโนมัติ) |

ข้อควรรู้เมื่อแก้เว็บต่อ:

- `connect-src 'self'` — หน้าเว็บเรียก API ได้เฉพาะโดเมนตัวเอง ถ้า `js/ewf-checker.js`
  ต้องเรียกฐานข้อมูล DBD ภายนอกโดยตรง ต้องเพิ่มโดเมนนั้นใน CSP ก่อน ไม่งั้นโดนบล็อก
  (ทางที่ถูกหลักกว่า: ให้เรียกผ่าน API ฝั่งตัวเอง เพื่อไม่เปิด CSP กว้าง)
- สคริปต์ทุกตัวต้องเป็นไฟล์ external ใน `js/` เท่านั้น — **ห้ามเขียน `<script>` inline
  และห้ามใช้ `onclick=` ใน HTML** ไม่งั้น CSP บล็อกและถือว่าผิดหลักที่วางไว้
- UI สร้าง DOM ด้วย `textContent` ทั้งหมด ไม่ใช้ `innerHTML` — รักษาหลักนี้ไว้กัน XSS
- ฟอร์ม ewf-checker เก็บข้อมูลติดต่อ → มี checkbox ขอความยินยอม PDPA อยู่แล้ว อย่าลบออก
